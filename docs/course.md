# HTMLとCSSで作品紹介ページを作る

はじめてコードを書く人が、素材と要望から作品紹介ページを組み立て、スマホとPCの両方で読める形で持ち出せることを、このコースの到達点とする。

| 学ぶこと | 自力でできるようになること |
|---|---|
| 文書の構造 | ページ名と本文を書き、見出し、段落、移動先のあるリンクに分ける。 |
| 展示の案内 | 持ち物と手順をリストで書き分け、短い原稿から入口、本文、末尾を組み立てる。章と作品紹介、重要な注意と言葉の強調を区別する。 |
| 展示の窓口 | 受付の方向を画像と代替文で伝え、公式サイトへのリンクを置く。欄の名前を押してメモを書き、消去して試せるカードを作る。 |
| 文字とCSS | 別ファイルのCSSを読み、どの段落にどの色が付くかを予測する。親から引き継いだ文字サイズと rem で指定したサイズを実測値で比べる。 |
| カードの見た目 | 作品をまとめ、文字、色、枠線、内側の余白を自分で指定する。 |
| 枠と押せる範囲 | 札の内側と外側を調整し、枠を含む幅を測る。狭い画面でも作品名を最後まで読み、リンクを文字の横から押せるようにする。 |
| 作者紹介 | 行間と配色を比べ、色以外でも選択中と分かる目印を付ける。複数のカードの主色を一か所から変える。 |
| Flexbox | 案内を並べる親と並ぶ作品を区別し、主軸・交差軸の配置を決める。作品を追加すると次の行へ回る列を作る。 |
| Grid | 入る枚数に合わせて作品棚の列数を決め、おすすめ作品を二列にまたがらせる。棚の外側の配置と、一枚の中のリンク配置を組み合わせる。 |
| 幅と画像 | スマホでページの表示幅を見比べ、内容に合わせて切り替える。横長・縦長の版画と説明が四つの幅で読み切れるようにする。 |
| 画面幅による配置 | 小さい画面では縦に、大きい画面では横にカードを並べる。 |
| キーボードと表示 | TabとEnterで展示を回り、現在地の枠、リンクや欄の名前、色を外した受付表示、動きを減らしたときの変化を確かめる。 |
| 卒業制作 | 別の題材の要望を読み、完成見本と比べながら自分でHTMLとCSSを書く。できたページは単体のHTMLとして開ける。 |
| 案内付きプロフィール制作 | 読者が知りたい順に章を決め、図書室の作者紹介を四工程で仕上げる。最後の練習からプロフィールを書き出し、卒業制作では別原稿の作品展に挑む。 |

## 教材を作る基準

JavaScriptの入口では、看板の文字、コンソールに出る値の種類、名前を付けた値、足し算、得点の更新を一つずつ扱う。実行時は教材画面と保存領域から分離したブラウザのWorkerを使い、下書きを保って停止・修正・再実行できる。

得点の次は、比較の真偽、二つの案内、三つの案内、問題番号の繰り返しを扱う。選んだ点の表示を見たあと、3点・6点の前後、問題数が0・1・3のケースでも同じコードが使えるか確かめる。

関数の章では、呼び出し、引数、戻り値、名前が使える範囲、矢印関数を別々に操作する。最後に二種類の加点を受け取る関数を作り、初回の結果を次の採点に渡して看板に合計を出す。

クロージャの章では受付ボタンを押すたびに、追加した呼び出しの行と実際のコンソール出力を対応させる。基本の受付から、毎回初期化される受付の修理と、二つの受付を独立させる発展練習を選べる。

問題集の章では、配列に名前を並べる、一件を位置で読む、順に読み上げる、題名と答えを一組にする、項目を名前で取り出す、の順に練習する。最後は別の原稿をもとに、並べ替えた一覧と一問だけの一覧から正答を読める問題集を作る。

問題集を加工する章では、全件の表示名、種類による絞り込み、空の一覧を含む点の合計、元を残すコピーを扱う。別原稿で絞り込みを外し、元の全件と新版の合計を同じ条件で比べられる。

- 1枚で疑問を一つ扱う。コードとその結果を一緒に載せ、どの例にも直接戻れるようにする。見本の表示には、掲載したコードを使う。
- はじめの操作は編集箇所と目に見える変化まで示す。続く操作は条件だけを示し、書き方を学習者に委ねる。
- 総合課題は、紹介したい作品と読者にしてほしい操作から始める。題材に迷う人にはタグのない原稿を用意する。一作品だけでも出来を確かめられ、必要なときにその工程のヒントと例を開けるようにする。
- 初めて扱う仕組みには使い道を示す。ページ内リンクは、作品メモへ実際に移動し、開始タグと属性、行き先の名前、リンクからの指定の順で学ぶ。
- 四択で読み方を確かめ、スマホではコードの一部をタップで組み立て、PCではコードを書く。どちらの端末でも練習方法を切り替えられる。四択、組み立て、記述の達成と下書きは別々に記録する。
- 正しい別解も通す。部分的に正しい解答には残る修正を一つ示す。該当スライドを見直しても、入力したコードから再開できる。
- 同じブラウザで途中の状態を保存し、端末間で進捗と下書きをファイルで受け渡せるようにする。

無料のHTML入門を2演習受講した際、見出しを書いた段階で残りの段落に絞った案内を受け、説明に戻っても書いた内容が残った。次の演習は一例を示してから、別の箇所にも自力で適用する流れだった。上の基準はこうした操作の観察を踏まえている。説明本文、題材、コード、設問は「よみくむ」用に制作する。[参考にしたコース](https://progate.com/courses/feature/html-css)

## 開発の区切り

教材のIssueにはその章で試せる操作と完了条件を書く。検証済みの同じ入力・配信物の結果は再利用し、保存や採点の共通変更は影響する操作をまとめて確かめる。勉強会や個人で無料で使える静的な構成とし、会員登録、決済、外部の実行サービスは必要としない。
